# AGENTS.md

Level-Up-addon — Minecraft Bedrock (MCPE) stats addon. Solo-leveling SYSTEM window: sneak + double-jump opens level / stat-points / STR-DUR-AGI screen.

## Layout (source of truth)

- `LevelUp_BP/` — behavior pack. `manifest.json` (format_version 2, `@minecraft/server` 2.0.0 + `@minecraft/server-ui` 2.0.0, `min_engine_version` [1,21,90]). Stable 2.0.0 shipped in Bedrock 1.21.90 — `min_engine_version` must not claim anything older, or the pack advertises an API the engine can't provide.
- `LevelUp_BP/scripts/main.js` — entire logic: gesture detect, XP/levels, SYSTEM form, STR/DUR/AGI effects. Balance knobs at top (`POINTS_PER_LEVEL`, `STR_DMG_PER_POINT`, `HP_PER_DUR`, `MAX_STAT`, `DUR_CAP`, `AGI_CAP`, `MAX_LEVEL` — see `README.md` Tuning table).
- Physical SYSTEM hologram: named `area_effect_cloud`s tagged `lu_holo` (`lu_owner`/`lu_slot`/`lu_until`/`lu_born` props), kept floating in front of the owner's view by a 5-tick interval. That keeper iterates the *entities* (scanning all three dimensions), not online players. Orphan clouds (owner logged out) are removed; through a portal the old-dimension clouds are removed and the board intent respawns in the new dimension — drive new cleanup from `holoEntities()`. Cosmetic layer only — the form is the source of truth.
- A script-spawned `area_effect_cloud` carries the vanilla `Duration` component (30 ticks) and the **engine despawns it by itself**; stable 2.0.0 has no `setComponent`, so a board left alone blinks out after ~1.5s. The board's intent therefore lives in the `holoBoards` map and the keeper *rotates* each line at `AEC_ROTATE_TICKS` — spawning the replacement **before** removing the old cloud, so a slot is never empty. Respawning only once a line is already gone leaves a 5-tick hole in the board every 30 ticks; do not "simplify" the rotation into a plain `if (missing) spawn`. `holoBoards` is keyed by player id and cleared in the `playerLeave` handler.
- Gestures: every jump funnels through `registerJump` (debounced by `JUMP_DEBOUNCE`) from two sources — the `playerButtonInput` event and a 1-tick velocity sampler. Do not raise the sampler's interval or its rising-edge threshold: jump velocity decays below ~0.35 within one tick, so a 2-tick loop watching `vy > 0.35` misses most jumps. `SNEAK_GRACE` exists because jumping out of a crouch clears `isSneaking` mid-gesture; it only continues a gesture already started while crouched. Dismiss = jump then sneak-start mid-air (`hasHologram` gates sound spam).
- `LevelUp_BP/pack_icon.png` — behavior-pack icon (128², tracked).
- CI: `.github/workflows/ci.yml` runs `node --check`, `node tests/run.mjs`, `node tests/coverage.test.mjs`, and `scripts/verify-pack.sh` (pack↔source parity + single-pack count). Build with `scripts/build-mcpack.sh`.

## Verify

- `node tests/run.mjs` — 35 assertions + `tests/stale-boost.test.mjs` isolation + `tests/coverage.test.mjs` (16) against a mock of the stable 2.0.0 surface in `tests/mock-server.mjs` (gesture, XP/levels, STR damage, DUR/AGI effects, hologram lifecycle, point spending, per-stat caps, foreign-effect safety, leaks, dismiss, cooldown, MAX_LEVEL, aura, portal). The mock models the area_effect_cloud self-despawn (`AEC_LIFETIME_TICKS`), because without it the holo board's survival over `HOLO_TICKS` is an assumption rather than a tested property. Also `node --check LevelUp_BP/scripts/main.js`, `npm run check`, and `scripts/verify-pack.sh`. In-game load test is still the final check.
- When adding a test, check it is not vacuous: run the suite against the *previous* `main.js` and confirm the new assertion actually fails there. A test that passes on the broken code proves nothing.
- Type-check against the real definitions when touching API calls: `npm pack @minecraft/server@2.0.0`, then `tsc --allowJs --checkJs --noEmit` over `main.js`. It catches read-only property writes and missing required options that the mock cannot.
- Keep Script API usage to stable 2.0.0 surface only (`world`, `system`, `ActionFormData`, dynamic properties, `health`/`speed`/`health_boost` effects) so `min_engine_version` [1,21,90] stays valid.
- Release convention: pack display name carries the version (`Level Up vX.Y.Z` in `manifest.json` header). Every update bumps all three together: header `name`, header `version`, and the `LevelUp_vX.Y.Z.mcpack` filename (only one current mcpack in the repo). Rebuild via `scripts/build-mcpack.sh` — `cd LevelUp_BP && zip -r ../LevelUp_vX.Y.Z.mcpack manifest.json scripts pack_icon.png` (zip the pack's *contents*, not the folder) + `scripts/verify-pack.sh` parity check.
- Every `EntityAttributeComponent` member is read-only in 2.0.0: `hp.effectiveMax = n` throws (modules are strict) and `hp.currentValue = n` silently no-ops — heal via `setCurrentValue`. `applyDurability` probes once, then maintains a `health_boost` effect; the probe is skipped while our own boost is up, or its inflated `effectiveMax` reads back as success after a reload. `health_boost` only steps in 4 HP, so the form reports real max HP via `maxHpOf`, never the ideal number.
- **Never clobber an effect you did not grant.** `addEffect` is documented as "adds or updates", so writing our amplifier unconditionally downgraded a stronger effect (a beacon grants Speed I/II) on every upkeep pass — only maintain ours when the active effect is absent or not stronger. `removeEffect` is worse: it is unconditional, so the Durability-0 cleanup only fires when the boost's amplifier matches the one recorded in `lu_boost_amp`. `lu_dur` never falls on its own, so an *unrecorded* boost is somebody else's (`/effect`, a datapack, another addon) and must be left alone. A boost from before that property existed can no longer be identified as ours and is deliberately left in place.
- **A stat must never sell a point that changes nothing.** Agility used to score `floor(agi / 5)`, so only agi 1/5/10/15/20 moved the Speed tier — 4 of every 5 points were no-ops that the form still called "Speed 5". Speed has exactly five tiers, so `agiAmplifier` is now one tier per point and `AGI_CAP` is 5; a point either steps a tier or `statCap()` refuses it. `statCap(key)` is the single source of truth for the ceiling per stat — never validate a purchase against `MAX_STAT` directly. Durability had the same shape with `HP_PER_DUR=2` (pairs quantized to one 4-HP step, so every even DUR was a no-op); `HP_PER_DUR` is now 4 with `DUR_CAP` 25, so each point is exactly one step. `loadStats` clamps legacy over-cap saves and refunds the excess as points.
- **A re-open must always leave the player a way out.** Re-opening on a maxed stat exists so points are not stranded, but only while `anySpendable()` holds. With every stat capped there is nothing to strand, and re-opening anyway trapped them: each tap re-opened the form, so **Close** was the only exit. The same gate applies after a successful spend, so spending the last point does not pop an empty form. Note the re-open lands 10 ticks after the spend, so a test that wants exactly one spend must stop before +12 ticks, and `formLog.shown` is global — count with a per-player filter or an earlier test's leftover chain will be counted against you.
- The `dur <= 0` branch of `applyDurability` must **not** be gated on `maxHpWritable`: it returns *before* the probe ever runs, so on a fresh session where no player has durability the flag stayed `undefined` forever and a phantom `health_boost` survived every upkeep pass. `tests/stale-boost.test.mjs` covers this in its own process — it cannot live in the shared suite, which has always flipped the flag to `false` by the time it gets there.
- `applyAgility(player)` is the single place granting the AGI `speed` effect; both the upkeep loop and `playerSpawn` call it. `playerSpawn` must not rely on the 100-tick upkeep loop alone or a respawn leaves the player at base speed for up to 5s. Like DUR, AGI records its amplifier (`lu_speed_amp`) and the agi-0 path only removes a matching boost, so a beacon/potion speed is never stripped.
- Tapping a stat that is already at `MAX_STAT` must re-open the form: the points are still spendable on the other two, and closing there strands them until the player redoes the whole gesture.
- STR bonus damage rides `entityHurt`, not `entityHitEntity`, and re-applies `originalDamage + bonus`. A bare `applyDamage(bonus)` lands inside the victim's i-frames and is discarded; the engine only applies the difference over the hit that opened the window, so the larger number nets exactly the bonus. Keep the `victim\x00hitter` 2-tick `bonusHitAt` guard (pipe `|` could collide — null byte never appears in Bedrock IDs) — our own `applyDamage` re-fires the event next tick, and 2 ticks is the minimum that blocks the recursion without eating legit spam hits. Drop its keys on `playerLeave` (handle both `|` legacy and `\x00`).
- Stable 2.0.0 has **no** `world.beforeEvents.chatSend`. Reading `.subscribe` off it throws at module top level, which aborts the whole script and silently disables the addon. Any optional event must be feature-detected inside a `try`; `/scriptevent lu:stats` is the supported fallback.
- All FX helpers in `main.js` (`safeSound`, `safeCommand`, `burstAt`, `spiralUp`, `levelUpCinematic`) are best-effort try/catch — keep that pattern for any new juice. Particle ids fall back through candidate lists; camera shake/fade are `runCommand` and need cheats ON.
- `MAX_LEVEL=100` caps the `while (xp >= xpNext)` loop — a corrupt `lu_xp=1e9` would otherwise freeze the tick. `loadStats` clamps `lu_level` and caps `lu_xp` at max, `entityDie` bails with `MAX LEVEL` feedback. Extra `ups>200` break is belt-and-suspenders.
- Clearing a dynamic property must be `setDynamicProperty(key, undefined)` — one-arg `setDynamicProperty(key)` can throw on some Bedrock builds and leaves stale `lu_boost_amp`/`lu_speed_amp`.
- `holoEntities()` unions the three vanilla dimensions + `holoSpawned` set — so a future custom dimension doesn't leak `area_effect_cloud`s. `spiralUp` checks `player.isValid` each tick; `openSystemAnimated` centralizes `UI_COOLDOWN` so scriptevent/gesture/chat can't stack forms.
- `DIMENSION_IDS` is the only hardcoded dimension list — stable 2.0.0 has exactly three; don't expand without a fallback scan (see `holoSpawned`).
